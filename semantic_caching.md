# Semantic Query Cache — Implementation Plan (v2)

## Overview

The cache wraps the LLM synthesis call in `kb_search_agent.py`. On every query:
embed → similarity-search the cache table → return hit if within the distance
threshold, otherwise call the LLM and write the result. Invalidation fires on
document delete and on ingest completion. Expiry is **lazy**: `get` filters
`expires_at > NOW()`, and `set` deletes expired rows opportunistically — no
pg_cron, no custom Postgres image, no request-path dependency on a scheduler.

Changes from v1 (rationale in *Design notes* at the bottom):

- **Dropped pg_cron** (and the custom Postgres Dockerfile). Correctness never
  depended on it — `get` already filters expired rows — so cleanup moves into
  `set()`. This removes the image build, the `shared_preload_libraries`
  command override on the instance that also backs Temporal, the manual
  migration step, and the managed-Postgres portability concern.
- **HNSW instead of ivfflat.** ivfflat computes its cluster centroids at
  `CREATE INDEX` time; built on an empty table it has degenerate lists and
  permanently poor recall. HNSW builds incrementally and needs no training data.
- **Model-aware entries.** Rows carry `llm_model_name`; `get` filters on the
  current model so a model switch can't serve answers generated by another model.
- **No caching of no-context answers.** If retrieval returned zero documents,
  the answer is not written: it would change as soon as a document is ingested,
  and with no source names it could never be invalidated.
- **psycopg3 SQL** (`%s` placeholders — matching `documents_routes.py`), the
  TTL parametrized via `make_interval` instead of an f-string, and the distance
  actually selected so the threshold check is possible.
- **Confluence ingest invalidation descoped** — that loader has no
  `document_name` identity today (see *Out of scope*).
- **Added phases for unit tests and doc updates** (mandatory per robots.md §7–9).

## Phase 1 — Postgres infrastructure

### 1a. Cache schema init file (`init-semantic-cache.sql`)

Mounted alongside the existing `init-pgvector.sql`. Numbered prefix ensures
ordering at first boot.

```sql
-- Runs after 01-pgvector.sql, which creates the vector extension.

-- vector(768) matches sentence-transformers/all-mpnet-base-v2 (HF_EMBED_MODEL
-- default). If HF_EMBED_MODEL changes to a model with a different output
-- dimension, this table must be dropped and recreated with the new dimension;
-- inserts will fail loudly (pgvector dimension mismatch) until then.
CREATE TABLE IF NOT EXISTS semantic_query_cache (
    id               UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    query_text       TEXT        NOT NULL,
    query_embedding  vector(768) NOT NULL,
    response         TEXT        NOT NULL,
    source_doc_names TEXT[]      NOT NULL DEFAULT '{}',
    llm_model_name   TEXT        NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at       TIMESTAMPTZ NOT NULL,
    hit_count        INTEGER     NOT NULL DEFAULT 0,
    last_hit_at      TIMESTAMPTZ
);

-- HNSW: incremental index, no training step, works correctly from row one.
CREATE INDEX IF NOT EXISTS idx_sqc_embedding
    ON semantic_query_cache USING hnsw (query_embedding vector_cosine_ops);

CREATE INDEX IF NOT EXISTS idx_sqc_expires_at
    ON semantic_query_cache (expires_at);

CREATE INDEX IF NOT EXISTS idx_sqc_doc_names
    ON semantic_query_cache USING GIN (source_doc_names);
```

### 1b. `docker-compose.yml` — postgresql service

Only one change: add the init file as a second mount. The image, command,
environment, and healthcheck stay exactly as they are.

```yaml
volumes:
  - postgres_data:/var/lib/postgresql/data
  - ./init-pgvector.sql:/docker-entrypoint-initdb.d/01-pgvector.sql:ro
  - ./init-semantic-cache.sql:/docker-entrypoint-initdb.d/02-semantic-cache.sql:ro
```

> **Note**: renaming the existing mount target to `01-pgvector.sql` is safe —
> init files only run on first boot (empty `postgres_data` volume). On existing
> deployments apply the schema manually once:
> `docker compose exec postgresql psql -U app -d app -f /docker-entrypoint-initdb.d/02-semantic-cache.sql`

## Phase 3 — `SemanticQueryCache` service (`framework_base/semantic_query_cache.py`)

New class. Four operations:

| Method | Caller | Transport |
|---|---|---|
| `async get(query) → Optional[str]` | `kb_search_agent` | async psycopg |
| `async set(query, response, source_doc_names)` | `kb_search_agent` | async psycopg |
| `async invalidate_by_document(doc_name) → int` | `documents_routes` | async psycopg |
| `sync_invalidate_by_document(doc_name) → int` | RAG loaders | sync psycopg |

Connections are opened per-operation from `settings.postgres_dsn` — the same
pattern `documents_routes.py` uses today (a shared pool is a later optimization,
noted in *Design notes*).

**Embedding**: `HuggingFaceEmbeddings(model_name=settings.hf_embed_model,
model_kwargs={"device": settings.embed_device},
encode_kwargs={"normalize_embeddings": True})` — the same construction as
`framework_base/vector_store.py`, so distances are on the same normalized scale.
Two constraints:

- **Lazy-loaded** on first `get`/`set`, not in `__init__` — the rag-worker only
  ever invalidates and must not pay the model load.
- `embed_query` is synchronous and CPU-bound; async callers run it via
  `asyncio.to_thread(...)` so it never blocks the event loop.

Embeddings are serialized to a pgvector literal (`"[f1,f2,...]"`) and passed as
a **parameter** cast with `%s::vector` — never interpolated into SQL.

**`get`** — embed the query, then:

```sql
SELECT id, response, query_embedding <=> %s::vector AS distance
FROM semantic_query_cache
WHERE expires_at > NOW()
  AND llm_model_name = %s
ORDER BY distance
LIMIT 1
```

pgvector's `<=>` returns cosine **distance** (0 = identical, 2 = opposite). A
hit is `distance <= 1 - settings.semantic_cache_similarity_threshold`
(threshold 0.92 → distance ≤ 0.08). Log the distance on every lookup (hit or
near-miss) — this is the tuning signal for the threshold. On a hit, bump stats
in a background task (`asyncio.create_task`) whose exceptions are caught and
logged, never raised:

```sql
UPDATE semantic_query_cache
SET hit_count = hit_count + 1, last_hit_at = NOW()
WHERE id = %s
```

**`set`** — embed the query, then in one transaction:

```sql
INSERT INTO semantic_query_cache
    (query_text, query_embedding, response, source_doc_names,
     llm_model_name, expires_at)
VALUES (%s, %s::vector, %s, %s, %s, NOW() + make_interval(hours => %s));

-- Opportunistic cleanup: lazy expiry + LRU cap. Cheap (both indexed), and it
-- only runs on cache misses, which already paid for a multi-second LLM call.
DELETE FROM semantic_query_cache WHERE expires_at < NOW();

DELETE FROM semantic_query_cache
WHERE id IN (
    SELECT id FROM semantic_query_cache
    ORDER BY COALESCE(last_hit_at, created_at) DESC
    OFFSET %s   -- settings.semantic_cache_max_entries
);
```

`set` is skipped entirely when `source_doc_names` is empty (see Phase 4).

**`invalidate_by_document`** (both variants):

```sql
DELETE FROM semantic_query_cache WHERE %s = ANY(source_doc_names)
```

Returns the deleted-row count for logging. **Never raises** — catches, logs a
warning with context, and returns 0. Invalidation is best-effort; TTL is the
backstop.

**All cache operations degrade gracefully**: any Postgres error in `get`/`set`
is caught and logged, and the caller proceeds as if the cache missed. A cache
outage must never take down KB search.

**Singleton**: module-level `_cache_instance: Optional[SemanticQueryCache]`
with a `get_semantic_cache() → SemanticQueryCache` factory, so the embedding
model loads at most once per process.

## Phase 4 — KB Search integration (`agents/kb_search_agent.py`)

### 4a. Refactor `_retrieve_rag_context`

Change return type from `str` to `tuple[str, list[str]]`. The second element is
the ordered, deduplicated list of `document_name` values from `doc.metadata`
across retrieved docs — **skipping docs where the key is absent** (Confluence-
ingested chunks carry no `document_name`; a placeholder like `"unknown"` would
be un-invalidatable noise). Private method, no external callers — not a
breaking change. The existing failure path returns `("", [])`.

### 4b. Wrap `search()`

```
search(query):
  if cache enabled:
      hit = await cache.get(query)          # errors inside → treated as miss
      if hit: return hit                    # early exit, no retrieval, no LLM

  rag_context, source_doc_names = await _retrieve_rag_context(query)
  prompt = _build_prompt(query, rag_context)
  response = await llm.ainvoke(...)

  if cache enabled and source_doc_names:    # never cache no-context answers
      await cache.set(query, response.content, source_doc_names)

  return response.content
```

`KnowledgeBaseSearchAgent.__init__` calls `get_semantic_cache()` only when
`settings.semantic_cache_enabled` is true; otherwise `self.cache = None`.

## Phase 5 — Delete path invalidation (`routes/documents_routes.py`)

After the existing `docstore.mdelete(doc_ids)` block succeeds in
`delete_document()`:

```python
if settings.semantic_cache_enabled:
    deleted = await get_semantic_cache().invalidate_by_document(document_name)
    logger.info(
        "Invalidated %d semantic-cache entries for document '%s'",
        deleted, document_name,
    )
```

One call into the `framework_base` service — the route stays thin.
`invalidate_by_document` never raises, so the HTTP response is unaffected by
cache failures.

## Phase 6 — Ingest path invalidation (rag-worker)

Two loaders (the Confluence loader is descoped — see *Out of scope*):

- `RAG/loaders/pdf_loader.py` → `ingest_pdf(file_path, document_name)`
- `RAG/loaders/text_loader.py` → `ingest_text_file(file_path, document_name)`

Invalidation runs at **ingest completion** (after the new chunks are committed
to pgvector + docstore), not at the start:

- *At-start* leaves a race: during a long ingest (LLM summarization takes
  minutes), queries still retrieve the old chunks and re-populate the cache;
  those stale entries then outlive the ingest until TTL.
- *At-completion* is also correct on failure: if ingest aborts midway, the old
  content is still what retrieval serves, so the old cache entries are still valid.

Pattern for each:

```python
from framework_base.semantic_query_cache import get_semantic_cache
from settings import settings

def ingest_pdf(file_path: str, document_name: str) -> dict:
    # ... existing ingestion unchanged ...
    if settings.semantic_cache_enabled:
        deleted = get_semantic_cache().sync_invalidate_by_document(document_name)
        logger.info(
            "Invalidated %d semantic-cache entries after ingesting '%s'",
            deleted, document_name,
        )
    return result
```

No try/except needed at the call site — `sync_invalidate_by_document` never
raises. Fires on first ingest (no-op) and re-ingest (clears stale entries).
The rag-worker image copies the full repo (`COPY . /app`), so
`framework_base/semantic_query_cache.py` and root `settings` are available
after `--build`.

## Design notes & accepted risks

- **Threshold semantics**: distance ≤ `1 − threshold` with normalized mpnet
  embeddings. 0.92 is deliberately conservative; the classic false-positive is
  negation/antonym pairs (“how do I *enable* X” vs “*disable* X”) which can
  embed very close. The logged distance on every lookup is the tuning data;
  the threshold is env-tunable without a deploy.
- **Cache stampede**: N concurrent similar misses → N LLM calls and N
  near-duplicate rows. Harmless at current traffic (rows dedupe functionally via
  nearest-neighbor lookup; extras expire). Single-flight locking is deliberately
  out of scope.
- **Delete/query race**: a query in flight during a document delete can write a
  cache entry referencing the deleted doc *after* invalidation ran. Window is
  seconds; TTL bounds the damage. Accepted.
- **Prompt/model coupling**: entries are filtered by `llm_model_name`, so model
  switches are safe. Prompt-template changes still require a manual flush
  (`DELETE FROM semantic_query_cache;`) — documented as a CLAUDE.md gotcha.
- **Cross-user visibility**: the KB is a single shared corpus with no per-user
  scoping today, so a shared cache matches the existing trust model. **If
  per-user document scoping is ever added, the cache must key on that scope or
  be disabled** — otherwise it becomes a cross-tenant leak. Flagged here so the
  future change can't miss it.
- **Growth/DoS bound**: every unique miss inserts a ~3 KB row. TTL bounds age;
  `SEMANTIC_CACHE_MAX_ENTRIES` (LRU on `COALESCE(last_hit_at, created_at)`)
  bounds size even under adversarial unique-query traffic.
- **Expired rows between misses**: cleanup only runs on `set`, so expired rows
  linger while traffic is all-hits or idle. `get` filters them (`expires_at >
  NOW()`), so they cost only disk — accepted for the simplicity of not running
  a scheduler.
- **Filtered ANN caveat**: HNSW returns nearest candidates before the
  `expires_at`/model filter applies; with `LIMIT 1` and a mostly-live table
  this is fine. If hit-rate ever degrades on a large, mostly-expired table,
  pgvector ≥ 0.8 iterative scans are the fix.
- **Connections**: per-operation connects match the existing
  `documents_routes.py` pattern. This Postgres instance also backs Temporal —
  if connection pressure appears, a `psycopg_pool.AsyncConnectionPool` in the
  cache service is the follow-up, not more per-call connects elsewhere.
- **Embedding dimension**: `vector(768)` is fixed at table-creation; a
  different `HF_EMBED_MODEL` dimension makes inserts fail loudly with a
  pgvector dimension error — remediation (drop + recreate) is commented in the
  SQL file.

## Out of scope

- **Confluence ingest invalidation** — `load_confluence_content()` takes no
  `document_name` and stamps no `DOC_NAME_KEY` metadata, so there is no
  identity to invalidate by; cache entries whose sources include
  Confluence-only content rely on TTL. Giving Confluence ingestion a document
  identity is a separate change; invalidation slots in trivially once it exists.
- No cache warming — entries are only written on cache miss.
- No metrics endpoint — `hit_count` / `last_hit_at` are queryable via SQL.
- No single-flight deduplication of concurrent identical misses.
- No invalidation on Confluence live-fetches from the collector agent (those
  bypass the ingest pipeline entirely).
- Coding agents untouched — no repetition pattern to benefit from caching.
